## What's in this release

### Contention & correctness
- **Partial-unique-index oversell guard** on `reservation_seats
  (show_id, seat_id) WHERE status IN ('HELD','CONFIRMED')` — the
  database itself rejects a second live hold for the same seat.
- **Reservation state machine** with explicit HELD / CONFIRMED /
  RELEASED / EXPIRED transitions; 100 % branch coverage enforced by
  JaCoCo.
- **Idempotent hold endpoint** on client-supplied `Idempotency-Key`.

### Eventing
- Kafka in KRaft mode via Compose, apache/kafka:3.8.0.
- **Transactional outbox** — service state and Kafka event enqueue in
  one DB transaction; a polling publisher marks rows sent.
- **CQRS availability projection** on catalog-service, invalidating a
  Redis cache on each event.
- **DLQ + retry with backoff** for poison messages.

### Saga
- **Orchestrated saga** (state machine in `BookingSagaOrchestrator`,
  durable in `saga_instances`) — the happy path is
  `SeatsHeld → PaymentRequested → PaymentAuthorized → Confirmed`.
- **Compensation** for `PaymentFailed`, hold-expiry-mid-saga, and
  late-auth-after-expiry.
- **Crash recovery**: `SagaRecoverySweep` at boot + a periodic
  scheduler re-drives any saga stuck past its deadline.
- Mock payment service with configurable failure rate for testing
  compensation and retry.

### Observability
- **Structured JSON logging** via logstash-logback-encoder.
- **correlationId MDC** threaded through the HTTP servlet filter and
  Kafka consumers. The same correlationId appears in booking and
  payment logs for one saga.

### CI / Ops
- Shared reusable CI workflow: TruffleHog → `mvn verify` → Docker
  build → Trivy → GHCR push (`main` only).
- Branch protection scripted on all 9 repos.
- Nightly e2e (clone-all → compose up → smoke).
