**Kubernetes-native platform — raw manifests on kind, Terraform for an
Azure k3s VM, a Helm umbrella chart, a shared single-Postgres-instance
data layer, Strimzi Kafka, Sealed Secrets, NetworkPolicy + pod-security
hardening, Ingress + Let's Encrypt via DuckDNS, a nightly backup CronJob,

(ADR-0004).**

## GitHub release body

```markdown
# STAMPEDE v0.3.0 — Milestone 3

**Kubernetes-native platform, replacing Sprint 2's Docker Compose stack
with kind/k3s, Helm, Strimzi Kafka, a shared Postgres instance, and
removing the temporary Eureka/Config Server scaffolding now that K8s
owns service discovery and configuration.**

## What's new in v0.3.0

### Local Kubernetes (kind) — STMP-37
- Raw manifests per service (`<service>/k8s-local/`), probes
  (liveness/readiness/startup via Actuator), resource requests/limits,
  ConfigMap-driven config, Secret-mounted credentials. Precursor to each
  service's own Helm chart.

### Helm umbrella chart — STMP-39
- Each of the 6 backend services ships its own `helm/` chart, published
  to `ghcr.io/stampede-io/charts` as an OCI artifact on every merge to
  `main`. `platform/charts/stampede/` composes them plus Postgres, Redis,
  and Kafka into one installable release, with `values-staging.yaml` /
  `values-prod.yaml` overrides.

### Shared data layer — STMP-40 (ADR-0006)
- One Postgres instance, five databases, five non-superuser credentials
  — `REVOKE ALL ... FROM PUBLIC` enforces the ownership boundary at the
  permission layer, not the process layer. Verified live: each service's
  user can reach only its own database. Redis for TTL holds and
  availability caching.

### Kafka on Kubernetes — STMP-41 (ADR-0007)
- Strimzi operator, single-broker KRaft mode, all 6 topics + DLQs as
  `KafkaTopic` CRDs, Prometheus metrics via a `PodMonitor`. Honest about
  scale: RF=3 across three brokers is the production answer, this is
  portfolio scale.

### Cloud provisioning — STMP-38
- Terraform for an Azure VM running k3s: resource group, VNet, NSG
  (80/443 open, 22 restricted to the operator's IP, 6443 closed), 64GB
  disk, remote state in Azure Storage.

### Secrets — STMP-45
- Sealed Secrets controller; no plaintext secret in any repo.

### Security hardening — STMP-46
- NetworkPolicies enforcing least-privilege traffic (`default-deny-all`
  plus explicit allow rules per dependency); non-root containers,
  read-only root filesystem, dropped capabilities.

### Public access — STMP-43
- NGINX Ingress + cert-manager + Let's Encrypt via DuckDNS (no purchased
  domain), with a CronJob keeping DuckDNS's IP record current.

### Operational readiness — STMP-47, STMP-48
- Nightly Postgres backup CronJob to Azure Blob (cool tier, 30-day
  lifecycle) with a documented, actually-run restore drill. Demo mode:
  seeded synthetic data, nightly reset, visible demo credentials.

### The portfolio-defining change — STMP-44 (ADR-0004)
- Eureka and Config Server deleted across all 6 service repos plus
  `platform` — seven coordinated PRs, merged in dependency order, since
  a polyrepo can't show a cross-cutting change as one atomic commit.
  Kubernetes Service DNS and ConfigMaps/Secrets replace both; see
  ADR-0004 for why they were never load-bearing to begin with.
